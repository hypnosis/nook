## Context

Панели нужны два права macOS: запись экрана (снимки иконок под чёлкой) и Accessibility (нажатие настоящей иконки и перенос). При ad-hoc подписи права привязаны к хэшу конкретной сборки и слетают при каждой пересборке. Developer ID на машине нет.

Подпись ad-hoc нужна, чтобы проверять онбординг в условиях пользователя. Но при частых пересборках (отладка «Применить») права приходится выдавать заново по нескольку раз в час.

## Decision

Пока идёт разработка, `scripts/install-local.sh` собирает Nook через `bundle.sh`, переподписывает его самоподписанным сертификатом «Nook Local Dev» и ставит в `/Applications` (путь важен, см. ADR 008). Место помечено `HARDCODE`. Релизные `bundle.sh` / `make-dmg.sh` по-прежнему подписывают ad-hoc.

Перед релизом скрипт возвращается к ad-hoc, а сертификат удаляется из связки ключей (спринт 09).

## Consequences

- Права переживают пересборку, отладка идёт без повторной выдачи прав.
- Онбординг и выдачу прав локально проверить нельзя: для этого нужна сборка из DMG или временный возврат к ad-hoc.
- После перехода с одной подписи на другую права слетают один раз. В Системных настройках может остаться прежняя запись Nook с включённым тумблером, которая уже не действует: её выключают и включают заново или удаляют и выдают право снова.
- Права, переживающие обновление у пользователя, появятся с Developer ID (спринт 07).

## Alternatives

- **Ad-hoc и локально.** Похоже на релиз, но права слетают на каждой сборке — на время разработки отвергнуто, вернётся перед релизом.
- **Developer ID.** Правильный путь, но аккаунта разработчика пока нет — переход в спринте 07.
