# 020 — Правда — строка меню: порядок читается из строки, иконки переносятся по одной

> Принято 2026-10-04, реализация в работе. Заменяет модель «реестр задумал — „Применить“ догоняет» из ADR 013. Способ переноса из ADR 019 остаётся.

## Context

Nook хранил порядок иконок как «должно быть» (реестр) и по кнопке «Применить» догонял им строку меню. Почти все баги последних спринтов — расхождения этих двух правд: реестр думает одно, строка стоит иначе. Чтобы их свести, появились добивочные проходы, выталкивание в чёлку, пересоздание разделителя, сверка «всё ли встало» и цепочка таймеров. Каждая заплатка добавляла новый случай.

Пробы 2026-10-04 показали две вещи:

- Адресный перенос (ADR 019) двигает любую иконку за 70–90 мс, в том числе спрятанную под чёлкой, если известен процесс её приложения.
- Настоящий порядок всех иконок, включая спрятанные, можно прочитать из системы. Нужно только читать в правильный момент (см. «Что выяснили»).

Ice устроен так же: строка — правда, каждый бросок в редакторе — один перенос.

## Decision

### Правила

1. **Правда — строка меню.** Своё состояние Nook сверяет со строкой, а не наоборот. Ручной Cmd+drag, новая или пропавшая иконка у приложения (Stats, Vorssaint) — обычные события, их ловит сверка.
2. **Одно состояние — один список:** `[панель …] разделитель [основной ряд …]`. Ряд иконки — сторона разделителя. Других флагов нет.
3. **Одна операция — перенести одну иконку.** Ей пользуются бросок в редакторе и расстановка вокруг неподвижной иконки. Шаги всегда одни: адресный перенос → проверка → запись.
4. **Одна очередь.** Пока идёт перенос, редактор заблокирован, следующий бросок ждёт.

### Скетч

```
                ┌──────────────┐
  строка меню ─▶│ Чтение строки│── порядок + доверие ──┐
                └──────────────┘                       ▼
                       ▲                        ┌────────────┐
                       │ проверка               │  Зеркало   │──▶ Редактор, Панель
                ┌──────────────┐  удачный перенос│ (на диске) │
  бросок ──────▶│   Перенос    │────────────────▶└────────────┘
                └──────────────┘
```

- **Чтение строки** — единственное место, которое знает, откуда берётся порядок. Собирает три источника по каждой иконке (окно, Accessibility, Preferred Position), раскладывает слева направо и говорит, можно ли этому порядку доверять целиком.
- **Зеркало** — последний известный порядок строки, ключ иконки — «приложение + имя иконки» (имя окна: `Item-0`, `nook-divider`, `VorssaintMenuBarItem.2`). Сохраняется на диск, переживает перезапуск Nook. Меняется только сверкой со строкой и нашим удачным переносом.
- **Перенос** — один адресный перенос иконки к соседу или к разделителю, запасной путь — перетаскивание (ADR 019). Иконка не встала — зеркало не меняется, плитка возвращается.
- **Редактор и панель** рисуют зеркало. Что на экране, то Nook и считает правдой.

### Сверка со строкой

- **Порядку можно доверять целиком**, когда ни одна иконка не стоит под чёлкой. Тогда зеркало просто принимает порядок строки.
- **Если часть иконок под чёлкой**, видимые берутся из строки, а спрятанные сохраняют порядок зеркала. Появилась новая спрятанная — в конец панели. Пропала — убирается.
- **Когда читать.** Строка читается при широком разделителе: иконки панели стоят за левым краем экрана с честными координатами, основной ряд виден. Пока открыт раздел «Расположение», разделитель узкий, и часть иконок может уйти под чёлку. В это время зеркало ведут наши переносы, а при закрытии раздела строка читается заново.

### Правила реализации

- **Чтение само говорит, можно ли ему доверять.** Под чёлкой нет ни одной иконки — порядок верен целиком. Разделитель узкий (открыт раздел «Расположение» или панель, ADR 016) — строку не читаем как правду.
- **Чтение и перенос — через одну очередь.** Прочитать строку посреди анимации переноса — получить полупорядок.
- **Два уровня чтения.** Дешёвый тик — только список окон (≈ 20 мс): появилось или пропало окно, сменился порядок видимых. Полное чтение с Accessibility (≈ 110 мс по всем приложениям) — только по такому изменению, при старте, при открытии и закрытии раздела.
- **Владельцы иконок находятся при полном чтении.** В доверенном состоянии x честные у всех, поэтому окно сопоставляется с иконкой приложения по ближайшему x с допуском (у крайних левых расхождение до 8 pt).
- **Зависшее приложение не держит чтение.** Короткий тайм-аут на приложение; не ответило — его иконки берутся из зеркала.
- **Внутри сеанса — номер окна, на диске — ключ «приложение + имя».**

### Неподвижная иконка

Если иконка не принимает перенос (Little Snitch), её не двигаем. Остальные встают вокруг неё той же операцией «перенести», по одной, каждая записывается в зеркало. Пометка «неподвижна» хранится по ключу до конца сеанса, чтобы не тратить ≈ 1 с на каждую попытку.

### Автоматическое расположение

Ложится на ту же модель (ADR 018): зеркало без разделителя, панель — иконки, которые не нарисованы.

### Что уходит

Кнопка «Применить» и её цепочка таймеров, реестр «как должно быть», добивочные проходы, выталкивание в чёлку, пересоздание разделителя после переноса, итоговая сверка «всё ли встало», заморозка реестра на время «Применить». Новый путь пишется отдельным модулем рядом со старым, старый удаляется целиком, когда новый заработает.

## Что выяснили (пробы 2026-10-04, Tahoe, MacBook с чёлкой)

### Координаты

| Источник | Единицы | Видимая иконка | За левым краем экрана | Под чёлкой |
|---|---|---|---|---|
| Окно (список окон, `kCGWindowBounds.X`) | x экрана, pt | честный, `0…ширина экрана` | **честный, отрицательный** (−1669 … −559) | ненадёжен: окно «не нарисовано», x — ближайшее свободное место |
| Accessibility (`AXPosition` иконки в `AXExtrasMenuBar` приложения) | x экрана, pt | x окна − 1 | **честный, отрицательный**, совпадает с окном | ненадёжен: в пробе AdGuard стоял правее Time Machine, хотя на деле левее |
| `NSStatusItem Preferred Position <имя>` в настройках приложения | расстояние от правого края, условные pt | — | — | — |

- **Знак координаты не важен.** Порядок — это сортировка по x по возрастанию, отрицательные x просто левее экрана. Ширина широкого разделителя сдвигает всё левее него за край, порядок при этом сохраняется.
- **Preferred Position — другая шкала.** Это не координата экрана, а ключ порядка: больше значение — иконка левее. Сравнивать его с x нельзя, только порядком. macOS переписывает его при переносе — и ручном, и нашем адресном. Часть записей устаревает (у приложений, которые давно не двигали иконку), поэтому как единственный источник он ненадёжен.

### Сверка источников

| Срез | Окно | Accessibility | Preferred Position |
|---|---|---|---|
| Строка свёрнута, всё левее спейсера за краем | порядок верный | тот же | тот же |
| Раздел открыт, одна иконка под чёлкой | спрятанная — «x = 811», неясно | спрятанная — x = 818, порядок с соседом не сходится с другими срезами | не изменился |
| После ручного Cmd+drag (Ollama на одну левее) | видно | видно | обновился у обеих иконок |

### Перенос спрятанной иконки

| Что | Результат |
|---|---|
| Адресный перенос иконки под чёлкой к соседу | 3 из 3, ≈ 86 мс, на месте через ≈ 140 мс |
| Процесс приложения иконки | был известен по прошлому показу; иконку, которую ни разу не видели, адресно не перенести — случай редкий, принимаем |

### Какой источник точнее

Не решено. Все три фиксируются в чтении строки. Окно и Accessibility дают одну шкалу и проверяют друг друга, Preferred Position — независимый ключ порядка. Расхождения пишутся в лог; по логу выбираем основной источник, остальные остаются самопроверкой.

## Consequences

- Каждый бросок в редакторе — один перенос, ≈ 130–180 мс вместо ≈ 700 мс у «Применить».
- Ручные перестановки и иконки, которые приложения добавляют и убирают сами, больше не ломают модель: их ловит сверка.
- Порядок переживает перезапуск Nook (ключи «приложение + имя»). Уходит баг «после запуска всё в панели».
- Иконки под чёлкой в открытом разделе читаются ненадёжно — в это время правда в зеркале, а не в строке. Риск: ручной Cmd+drag в открытом разделе виден только для видимых иконок.
- Чтение строки обращается ко всем приложениям через Accessibility (≈ 110 мс). Делать это при каждом тике нельзя — только при сверке.
- Код «Применить» удаляется целиком; пункты техдолга A и B спринта 09, связанные с ним, закрываются вместе с ним.
- Основной ряд длиннее места до чёлки — доверенного чтения не бывает: видимые из строки, спрятанные из зеркала. Ручной Cmd+drag спрятанных в этом случае не виден — принятый риск.
- Два запущенных экземпляра одного приложения дадут одинаковые ключи — редкий случай, принимаем.
- Разделитель по-прежнему может потерять место при пересоздании на старте (техдолг спринта 09) — модель его не пересоздаёт, но эта ловушка остаётся.

## Alternatives

- **Чинить реестр и «Применить» дальше.** Каждая починка открывала новый случай расхождения. Отвергнуто.
- **Только зеркало, без сверки со строкой.** Не видит ручные перестановки и иконки, которые приложения добавляют сами. Отвергнуто.
- **Только Preferred Position.** Ключ обновляется при переносе, но часть записей устаревает. Оставлен как самопроверка.
- **Читать строку при открытом разделе.** Иконки под чёлкой дают ненадёжный порядок. Отвергнуто — читаем при широком разделителе.
