# 09 — Техдолг после вычитки кода

Создан: 2026-10-03

## Цель

Вычитка перед ревизией нашла места, которые пока работают, но могут сломаться. Срочные баги
починены сразу, здесь — то, что отложено, чтобы не потерять.

## Объём работ

- [ ] Порядок иконок сохраняется на диск (`~/Library/Application Support/Nook/layout.json`) и переживает перезапуск. Нужны стабильные ключи иконок вместо номеров окон.
- [ ] Место разделителя ставится через приватный ключ `NSStatusItem Preferred Position`: проверять после каждого обновления macOS.
- [ ] Ширина «широкого» разделителя запоминается при входе в узкий режим и может устареть, если за это время поменялся набор иконок.
- [ ] Контроллер ведёт «Применить» через цепочку таймеров и флагов — свести к одному состоянию.
- [ ] Вызовы делегата по строковым селекторам (`msg_send!`) — опечатку не ловит компилятор.
- [ ] Таймеры и снимки панели без номера запроса: старый результат может перезаписать свежий.
- [ ] Опросы с тайм-аутом (`wait_divider`, `wait_until_still`) по истечении молча идут дальше.
- [ ] Несколько мониторов: чёлка, снимок шторки и «мышь в строке меню» берутся с разных экранов.
- [ ] Неподвижные иконки (Little Snitch) не запоминаются между «Применить».
- [ ] При выходе во время переноса мышь не возвращается.
- [ ] Логи собирают строку `format!` даже при выключенном логе; путь лога в общем `/tmp`.
- [ ] Bundle id повторяется в нескольких скриптах и в коде.
- [ ] Удалить сертификат «Nook Local Dev» из связки ключей.

### «Применить» ставит порядок не с первого раза

Симптом: выставил порядок, нажал «Применить» — порядок неверный; нажал ещё раз — верный.
Причина не подтверждена, подозреваемые (каждый объясняет, почему второй раз чинит):

- [ ] **H1. Разделитель пересоздаётся после проверки порядка.** `replace_divider` убирает и
  создаёт разделитель уже после переносов — строка сдвигается, а `landed` посчитан до этого.
  Во второй раз разделитель уже на месте и не пересоздаётся.
- [ ] **H2. Расставляются только видимые, добивочный проход один.** Пока иконки едут, другие
  выходят из-под чёлки или уходят под неё; `MAX_CORRECTIONS = 1` — после второго прохода mover сдаётся.
- [ ] **H3. Итоговая проверка неполная.** `landed` сравнивает только видимые, а реестру в конце
  записывается порядок редактора, даже если строка встала иначе.

Сначала улики: временный лог в сборке `debug-log` — время каждого переноса, упирание в тайм-аут
тишины, порядок до и после каждого прохода (с иконками под чёлкой), порядок до и после
пересоздания разделителя. Сценарий «Применить (плохо) → Применить (хорошо)», по логу выбрать гипотезу.

Из вычитки потока «Применить» (2026-10-04), не исправлено:
- [ ] `push_into_notch` считает хвост `order` без учёта спрятанного разделителя и вытаскивает
  в чёлку то, что только что поставил `arrange_all`; его переносы не логируются.
- [ ] Порядок редактора перечитывается 4 раза за прогон — пользователь может поменять его посреди
  переноса. Запоминать `(panel, main)` при старте.
- [ ] Флаг `apply_when_editor_ready` остаётся поднятым при ранних возвратах и срабатывает позже.
- [ ] `apply_result` не сбрасывается при отмене сторожем; таймеры сторожа не отменяются между прогонами.
- [ ] `hidden_in_wrong_row` сравнивает x спрятанных окон, когда разделитель не нарисован, — ложный `cramped`.
- [ ] При пересоздании своих элементов (retry-эскалация) macOS стирает их сохранённое место,
  и якорь со спейсером встают левее всех — под чёлку. Сохранять место перед удалением.

Набросок третьего подхода (после улик, не раньше):
- ждать конкретное условие «X уже правее Y» по порядку окон, а не тишину во всей строке —
  иконки с живой шириной (Stats) не мешают;
- ставить разделитель до переносов, а не пересоздавать после;
- добивать в цикле, пока порядок не совпал или перестал улучшаться;
- честная итоговая проверка по всей строке, включая иконки под чёлкой; реестру не врать.

## Критерий готовности

Каждый пункт либо сделан, либо осознанно закрыт как принятый риск.
