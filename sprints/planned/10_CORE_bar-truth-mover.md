# 10 — Правда — строка: реестр и перенос по одной иконке

Создан: 2026-10-04

## Цель

Заменить «Применить» моделью из ADR 020: строка меню — реальный порядок, реестр — желаемая
очерёдность, каждый бросок в редакторе — один перенос одной иконки. Nook сам иконки не двигает.

## Модель (согласовано с владельцем 2026-10-04)

- **Строка** — реальный индекс: какие иконки есть и где стоят.
- **Реестр** (`layout.rs`) — один список на всё: `[панель …] | [основной ряд …]`. Панель и редактор
  рисуются только из него.
- **Сверка на тике:** ряд иконки — сторона разделителя (честно везде, и под чёлкой); нарисованные
  иконки берут порядок строки; ненарисованные (панель, под чёлкой) держат место в реестре; новая
  встаёт за соседом слева по строке; пропавшая уходит.
- **Бросок** — один `mover::move_one` к соседу по редактору (между рядами сосед — разделитель).
  Внутри панели — только реестр. Не встала — плитка возвращается, пояснение.
- **Nook без действия пользователя ничего не двигает.** Вернувшаяся иконка стоит, где её поставила
  macOS, реестр принимает это.
- Под чёлкой: macOS собирает ненарисованные иконки левее нарисованных, вплотную. Порядок внутри
  группы честный, между группами — нет. Перенос под чёлкой работает (3 из 3, 85 мс).

## Критерий готовности

- Бросок плитки в любой ряд — иконка в строке встаёт за ≈ 200 мс, курсор не виден, двигается одна иконка.
- Иконка под чёлкой переносится так же.
- Ручной Cmd+drag видимой иконки и новая иконка видны в редакторе после ближайшей сверки.
- После перезапуска Nook ряды те же.
- Little Snitch: плитка возвращается, повтор мгновенный.
- Кода «Применить» в проекте нет. ✅
